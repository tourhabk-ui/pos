# Запись сервера Ведара на Glama — сборка из репозитория

Главный список MCP-серверов (`punkpeye/awesome-mcp-servers`, заявка #18155)
берёт строку только с записью **сервера** на Glama: запись по репозиторию
`tourhabk-ui/pos`, подтверждённая владельцем, с оценкой качества. Запись
`pos` на Glama есть, владелец её сопровождающий. Коннектор `ru.vedarai/mcp`
на Glama — другая запись.

## Почему не мост

Сначала (19.11, «Мост») образ был мостом `mcp-remote` к
`https://vedarai.ru/api/mcp`. 20.11 Glama не приняла оба поля: «cannot use
mcp-remote. The Dockerfile must build and run the server locally, not proxy
to an external endpoint». Всё приложение Ведара с базой в образ не собрать.
Владелец выбрал короткую сборку («3 да», 20.11).

## Что запускает образ

`server/server.mjs` — сервер MCP по stdio, без зависимостей и без базы:

- `initialize`, `ping`, `tools/list` — как у живого сервера; список — все
  инструменты Ведара с их настоящими описаниями и схемами (снимок
  `server/tools.json`);
- `tools/call` — ошибка инструмента (`isError`) со словами, что данных
  Камчатки в этой сборке нет, и с адресом живого сервера. Ответ данными здесь
  был бы выдумкой: каждому инструменту Ведара нужна база;
- запросов наружу сервер не делает: ни прокси, ни подмены ответа.

Снимок снимается с кода: `npx tsx scripts/glama-tools-snapshot.ts`.
Поменялись определения инструментов — снимок нужно снять заново, иначе сторож
краснеет.

## Значения формы Glama

Glama собирает образ по форме (основа `debian:trixie-slim` и Node 24 — её,
`mcp-proxy` ставит она же). Поля — JSON, **каждое одной строкой**, иначе
форма не принимает:

Build steps:

```
["node integrations/glama/server/server.mjs --self-check"]
```

CMD arguments:

```
["node","integrations/glama/server/server.mjs"]
```

Слов `mcp-proxy --` в CMD нет: Glama ставит их сама. Те же значения лежат в
`glama-build.json`, повтор образа — `Dockerfile` рядом. Пакетов шаг сборки не
ставит: серверу они не нужны.

## Шаги владельца на Glama

1. Дождаться, когда этот код окажется в `main`.
2. В записи сервера `pos` открыть вкладку администратора с Dockerfile.
3. Заменить оба поля значениями из раздела выше, сохранить и запустить
   сборку.
4. Дождаться, когда сборка пройдёт и у записи появится оценка.
5. Сказать в чате Ведара. Значок оценки в заявку #18155 добавляется только
   после этого и только по слову владельца.

## Что проверено и что нет

Проверено в контейнере разработки: самопроверка снимка, `initialize`,
`tools/list` (25 инструментов), отказ вызова; то же под `mcp-proxy` 6.9.0.

Не проверено: сборка у самой Glama (докера здесь нет), из какого каталога
Glama исполняет шаги (по её шаблону — из корня репозитория), и как её оценка
отнесётся к серверу, у которого вызовы отвечают «данных нет». Примет ли такую
запись проверяющий списка, решает он.

Владение записью подтверждает `glama.json` в корне: он называет
`tourhabk-ui`.

Сторож: `tests/unit/glama-local-server.test.ts`.
