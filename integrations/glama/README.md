# Запись сервера Ведара на Glama — мост к удалённому серверу

Главный список MCP-серверов (`punkpeye/awesome-mcp-servers`, заявка #18155)
берёт строку только с записью **сервера** на Glama: запись по репозиторию
`tourhabk-ui/pos`, подтверждённая владельцем, с оценкой качества. Сервер,
который нельзя собрать в контейнер, туда не попадает. Коннектор
`ru.vedarai/mcp` на Glama уже есть, но это другая запись.

Сервер Ведара удалённый — `https://vedarai.ru/api/mcp`, без ключа. Собирать
из репозитория нечего: это всё приложение Ведара с базой. Поэтому образ на
Glama — мост: `mcp-remote` превращает удалённый сервер в stdio, а `mcp-proxy`
Glama отдаёт его своему проверяющему. В образе нет ни данных, ни ключей;
каждый вызов идёт на прод Ведара, и отвечает прод. Путь выбрал владелец 19.11
(«Мост»).

## Значения формы Glama

Glama собирает образ по форме (основа `debian:trixie-slim` и Node 24 —
её). Поля — JSON, **каждое одной строкой**, иначе форма не принимает:

Build steps:

```
["npm install -g mcp-remote@0.15.2"]
```

CMD arguments:

```
["mcp-remote","https://vedarai.ru/api/mcp","--transport","http-only"]
```

Слов `mcp-proxy --` в CMD нет: Glama ставит их сама. Те же значения лежат в
`glama-build.json`, повтор образа — `Dockerfile` рядом. Версии закреплены
точно: мост, подтянувший новую версию сам, перестал бы быть тем, что
проверено.

## Шаги владельца на Glama

1. Войти на glama.ai через GitHub аккаунтом `tourhabk-ui`.
2. Добавить сервер по репозиторию `https://github.com/tourhabk-ui/pos`.
3. Подтвердить владение: `glama.json` в корне репозитория уже называет
   `tourhabk-ui`.
4. В настройках сервера вставить два поля из раздела выше, сохранить и
   запустить сборку.
5. Дождаться, когда сборка пройдёт и у записи появится оценка.
6. Сказать в чате Ведара. Значок оценки в заявку #18155 добавляется только
   после этого и только по слову владельца.

## Что проверено и что нет

Проверено 19.11 в контейнере разработки: `mcp-proxy` 6.9.0 → `mcp-remote`
0.15.2 → настоящий обработчик `/api/mcp`, поднятый локально: `initialize`
отвечает (`vedar-mcp` 2.10.2), `tools/list` — 25 инструментов, вызов
`get_volcano_status` возвращает текст.

Не проверено: сборка и проверка инструментов у самой Glama (докера здесь нет)
и путь до `vedarai.ru` с их машин. Примет ли мост проверяющий списка, решает
он.

Сторож: `tests/unit/glama-server-bridge.test.ts`.
