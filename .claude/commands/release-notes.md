Собери release notes по мержам в main за период: $ARGUMENTS (пусто — за последние 7 дней)

## Как собирать

1. `git log origin/main --merges --oneline --since=<период>` плюс squash-коммиты: `git log origin/main --oneline --since=<период> --grep="(#"` — в этом репо PR мержатся squash'ем, заголовок содержит номер PR.
2. Для каждого PR возьми суть из заголовка и тела squash-коммита (`git show <sha> -s --format=%B`) — там уже написано «что/почему» по-русски.
3. Сгруппируй по доменам платформы: Безопасность / Кабинеты партнёров / Каталог и витрины / Данные и импорты / Админка / Инфраструктура.
4. Пиши для читателя-нетехнаря (владелец, канал): что изменилось для пользователя, не какие файлы тронуты. Технические детали — одной строкой в конце пункта, если важны.
5. НЕ ВРАТЬ: только реально смерженное; фичи «в полёте» (открытые PR) — отдельным блоком «Скоро», если попросили.

## Формат ответа

```
Обновления TourHab — <период>

<Домен>
- <что изменилось для пользователя> (#NNN)
...
```

Коротко, без воды, эмодзи не использовать. Если за период мержей нет — так и скажи.
