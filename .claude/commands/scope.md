Оцени объём изменения ДО старта работы: $ARGUMENTS

## Как оценивать

1. Найди все файлы, которые придётся трогать (Grep/Glob по затронутым доменам), включая тесты и миграции.
2. Проверь пересечение с запретами §7 CLAUDE.md (`middleware.ts`, `lib/auth.ts`, `app/api/payments/`, `app/api/safety/sos`, миграции 001-049) — если задевает, это меняет подход (staging, отдельное согласование).
3. Проверь, нужна ли миграция БД (новая таблица/колонка) — если да, номер = следующий за максимальным в `migrations/`.
4. Оцени, есть ли готовые паттерны для переиспользования (похожие роуты/компоненты/хелперы) — назови их.
5. НЕ начинай реализацию — только оценка.

## Формат ответа

Короткая таблица:

| Параметр | Оценка |
|---|---|
| Размер | маленькое (1 файл) / среднее (2-5) / крупное (5+ или миграция) |
| Файлы | список ключевых |
| Миграция | нужна/нет (+ номер) |
| Риски §7 | задевает/нет |
| Готовые паттерны | что переиспользовать |
| Обязательный план (§5 CLAUDE.md) | да, если схема БД / авторизация / API / бронирования |

Плюс 2-3 предложения: неочевидные зависимости и что уточнить у владельца до старта.
