Разрули конфликты текущего merge/rebase.

## Как разруливать

1. `git status` — список конфликтующих файлов; `git log --oneline -3 HEAD MERGE_HEAD` (или rebase-цель) — что с чем сливается.
2. По каждому файлу: прочитай ОБЕ версии целиком (не только маркеры конфликта) — пойми, что делает каждая сторона и не исключают ли изменения друг друга семантически (компилирующийся результат может быть логически неверным).
3. Типовые случаи в этом репо:
   - две ветки добавили соседние пункты в один список (сайдбары, SIDEBAR_ITEMS, схемы Zod) — почти всегда нужны ОБА;
   - конфликт в миграциях — никогда не сливать в один файл: у каждой ветки свой номер, при коллизии номеров перенумеруй свою (следующий свободный);
   - конфликт в тестовых моках по тексту SQL — сверь с актуальным SQL роута, мок подгоняется под код, не наоборот.
4. Если резолюция неочевидна (стороны противоречат по бизнес-логике) — НЕ выбирай молча: покажи обе версии и спроси.

## После резолюции — обязательно

```
npx tsc --noEmit && npx vitest run
```

Конфликт «разрулен» только когда компилируется и тесты зелёные. В ответе перечисли по каждому файлу: чьё изменение сохранено и почему.
