Разбери ошибку БД и почини её везде, где она встречается: $ARGUMENTS

## Почему эта команда существует

В этом репо уже был случай (PR #266): один API-роут падал с `column ot.duration_days does not exist`, потому что код исторически копировал имена колонок из legacy-VIEW (`tours`, `agent_route_knowledge`), а не из реальной таблицы (`operator_tours`). Баг оказался не единичным — тот же паттерн (ссылка на несуществующую колонку) нашёлся ещё в 5 файлах. Эта команда формализует то, как это разбиралось.

## Шаги

1. **Не чини вслепую.** Сначала найди РЕАЛЬНУЮ схему: `grep -rn "CREATE TABLE <таблица>\|ALTER TABLE <таблица>.*ADD COLUMN" migrations/*.sql`. Если таблицы нет в `migrations/` — она могла быть создана до начала трекинга миграций; ищи через любые упоминания её колонок в существующих `ALTER`/`CREATE VIEW`.
2. Проверь, нет ли **legacy compat-VIEW** поверх этой таблицы (в этом репо есть минимум два: `tours` → `operator_tours`, `bookings` → `operator_bookings`, `agent_route_knowledge` → UNION `places`+`kamchatka_routes`) — они специально алиасят старые имена колонок под новые. Если код обращается к таблице напрямую (не через VIEW), но использует алиас из VIEW — это и есть баг.
3. Как только нашёл правильное имя колонки — **прогони Grep по всему репо** на то же самое неправильное имя рядом с той же таблицей (`grep -rn "\.<неправильная_колонка>\b"`), проверяя каждое вхождение: это та же таблица напрямую (баг, чинить) или JSONB payload/другая таблица, где имя совпадает случайно и колонка реальна (не трогать).
4. Почини каждое найденное место, алиасируя реальную колонку под старое имя в SELECT (`ALTER_реальное_имя AS старое_имя`), чтобы не переписывать JS-код ниже, который уже ждёт старое имя поля в ответе — только если не просили менять форму ответа.
5. `npx tsc --noEmit` и `npx vitest run` — обязательно перед тем, как считать готовым.

## Формат отчёта

- Реальная колонка / таблица (со ссылкой на миграцию, где она создана)
- Список всех исправленных файлов с номером строки
- Явно укажи, если что-то похожее нашёл, но НЕ тронул (например, JSONB payload с тем же именем ключа — легитимно) — чтобы не создавалось впечатление, что пропустил
