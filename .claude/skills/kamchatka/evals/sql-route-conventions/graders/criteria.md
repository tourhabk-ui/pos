Оцени код API route из ответа по конвенциям репозитория tourhabk-ui/pos (CLAUDE.md):

ОБЯЗАТЕЛЬНО (нарушение любого — это провал, оценка не выше 0.3):
- Таблица броней — `operator_bookings`, НЕ `bookings`.
- Колонка статуса брони называется `booking_status`, НЕ `status`.
- Фильтр по статусу исключает и отменённые, и отклонённые брони (два состояния, не одно).
- Импорт пула — именованный: `import { pool } from '@/lib/db-pool'`, НЕ `import pool from ...` и
  НЕ `from '@/lib/db'`.
- SQL параметризован (`$1`, `$2`...), никакой конкатенации строк или шаблонных литералов со
  значением tourId внутри SQL-текста.
- Нет `SELECT *` — явные колонки.

ЖЕЛАТЕЛЬНО (влияет на оценку слабее, но не ноль):
- Есть валидация входного параметра (например, что tourId передан и что это похоже на UUID/число).
- Ошибки БД не проглатываются молча (если есть try/catch — есть хоть какой-то лог отказа).

Ответ, который называет таблицу `bookings` или колонку `status`, или использует
`import pool from` без фигурных скобок, ДОЛЖЕН получить низкую оценку (0.0–0.3), даже если код
синтаксически корректен и в остальном аккуратен — это ровно те ошибки, ради которых скилл существует.

Оценка 1.0 — все обязательные пункты выполнены.
Оценка 0.5–0.7 — обязательные пункты выполнены, но упущено что-то из желательных.
Оценка 0.0–0.3 — нарушен хотя бы один обязательный пункт.
