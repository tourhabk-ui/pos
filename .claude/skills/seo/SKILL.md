# SEO Ведара — вход

Методология — из claude-seo v2.2.4 (MIT); под-скиллы `seo-*` лежат рядом и
используются как чеклисты. Этот файл — обвязка под НАШУ платформу: что здесь
иначе, чем предполагает оригинал.

## Особенности среды (важно, оригинал этого не знает)

1. **Прод недоступен из песочницы напрямую**: `curl https://vedarai.ru` →
   403 на CONNECT (политика egress-прокси). Живые страницы читать через
   **WebFetch** (он ходит через инфраструктуру claude.ai)… но и он получает
   403: Timeweb блокирует IP-диапазоны Anthropic. Рабочие пути:
   - **раннер GitHub Actions** — curl оттуда проходит (проверено 06.08:
     все краулерные UA получают 200). Одноразовый probe-workflow в рабочей
     ветке, удалить после снятия показаний;
   - **локальная прод-сборка** (`next build` + standalone) для рендера,
     структуры, заголовков — без данных БД часть страниц пустая, это
     ограничение назвать в отчёте;
   - **код** — метаданные, JSON-LD, canonical, robots, sitemap генерируются
     детерминированно, аудит по исходникам полноценен.
2. **Python-инструментов оригинала здесь нет** — работаем чеклистами
   скиллов, без их скриптов. Ничего не измеряем «на глаз»: чего нельзя
   измерить доступным путём, того нет в отчёте.
3. **Рунок**: главный поисковик — Яндекс. IndexNow уже подключён
   (`lib/seo/indexnow.ts`, ключ на `/indexnow.txt`, пинги при сохранении
   тура, bulk — `POST /api/admin/indexnow/bulk`).

## Карта платформы для аудита

| Что | Где |
|---|---|
| robots | `app/robots.ts` — AI-краулеры приглашены явно |
| sitemap | `app/sitemap.ts` — 779 мест, маршруты, туры |
| llms.txt | `app/llms.txt/route.ts` |
| MCP для агентов | `/api/mcp`, `/.well-known/mcp.json` |
| Метаданные | `generateMetadata` в `page.tsx` (176/210 страниц) |
| JSON-LD | страницы туров/мест/каталога/операторов |
| Ключевые публичные страницы | `/`, `/catalog`, `/marketplace/tours/[id]`, `/places/[id]`, `/routes/[id]`, `/safety` |

## Порядок аудита

1. `seo-technical` — по коду + probe с раннера при необходимости.
2. `seo-schema` — валидность JSON-LD по исходникам генераторов.
3. `seo-geo` — цитируемость: первый экран страниц мест/туров, вопросные
   заголовки, самодостаточные абзацы. Факты — только из БД (§8 CLAUDE.md):
   выдуманных цифр в «цитируемых блоках» быть не может.
4. `seo-sitemap`, `seo-content`, `seo-page` — точечно.
5. `seo-programmatic` — наш главный масштабный кейс: 779 страниц мест и
   294 маршрута генерируются из БД. Чеклист про thin content, index bloat,
   шаблоны и внутреннюю перелинковку — ровно про /places и /routes.
6. `seo-images` — 354 фото точек: alt, форматы, lazy, CLS. Части про
   DataForSEO/конвертацию файлов в песочнице не работают — только чеклист.
7. `seo-local` — региональный интент. ВАЖНО: скилл Google-центричен
   (GBP, map pack); для рунка читать через призму Яндекс.Бизнес и
   Яндекс.Карт — принципы (NAP, отзывы, location pages) переносятся,
   инструменты нет.

Отчёт — приоритизированный, каждая рекомендация с проверяемым критерием.
Найденное чинится PR'ами по слову владельца; правки контента мест/туров —
через кабинет или миграцию с названным источником.
