# Проверка безопасности Ведара

Метод взят из скилла vulnerability-scanner (репозиторий davila7/claude-code-templates,
лицензия MIT, автор Daniel Ávila) и пересказан под правила Ведара. Сторонний текст в
проект не копировался: слово владельца 26.11 «свой делай».

Первый прогон 26.11 по ИИ-части нашёл двенадцать находок и стал четырьмя PR (#3837,
#3840, #3843, #3845). На каждом из них ревью безопасности нашло ещё по одной-три дыры —
в самих исправлениях. Эти дыры собраны в разделе 3: это главное, чему учит прогон.

## Правила

- **Только чтение до слова владельца.** Итог — отчёт (раздел 5). Чинить — когда
  владелец скажет, по CLAUDE.md §5.
- **Чинит главная сессия** (CLAUDE.md §5.1). Помощники poisk и razbor-vyvoda
  ищут места и разбирают длинный вывод, кода не пишут.
- **Находка — прослеженный путь** от входа до вреда, с `file:line`. Без пути это
  зацепка, а не находка.
- **Каждую зацепку пытайся опровергнуть**: найди проверку, которая её закрывает, и
  попробуй её обойти. Опровергнуть не вышло — находка.
- **Прод не трогать.** Ни заявок, ни броней, ни проб записи. Каждый живой вызов MCP
  считается в статистике: только чтение, по одному, с названной целью.
- **Секреты, ПД, ключи и идентификаторы** не попадают в отчёт, issue, коммит и PR.
- **Чего не проверил — так и пишешь** (§4.0): «не смог проверить» не равно «чисто».

## 1. Карта входов

Сначала карта, потом код. По каждому входу три вопроса: кто пишет текст, куда он
попадает (промпт, аргумент инструмента, SQL, файл, сеть) и что после этого может
сделать модель или код.

| Вход | Где | Кто пишет | Что может |
|---|---|---|---|
| Чат Кузьмича на сайте | `app/api/ai/chat/route.ts`, поток — `app/api/ai/chat-stream/route.ts` | гость и вошедший | инструменты Кузьмича, заявки, траты |
| Виджет на сайте партнёра | `app/api/widget/chat/route.ts` | любой посетитель чужого сайта | траты, ответ от имени Ведара |
| Разговор агента по A2A | `app/api/a2a/_shared.ts`, `lib/a2a/chat.ts` | чужой агент без входа | траты, инструменты, журнал |
| MCP | `app/api/mcp/route.ts` | чужой агент без входа | инструменты, заявки |
| Помощник оператора | `lib/agents/sdk/operator-tools.ts`, `lib/agents/sdk/sdk-runner.ts` | оператор, а в выводе инструментов — туристы | цена, публикация тура |
| Зрение | `lib/ai/providers.ts` (`callVisionDetailed`) | человек со снимком | ПД (место съёмки) за границу |
| Судья, перевод журнала A2A, разбор группы | `lib/agents/managed/kuzmich-outcomes.ts`, `lib/a2a/dialog-translate.ts`, `lib/telegram/group-monitor.ts` | туристы, чужие агенты, участники групп | ПД за границу |
| Рука | `.github/workflows/claude.yml` | автор issue или комментария | правка репозитория с правом записи |
| Сессия Claude Code | `.claude/settings.json`, `.claude/hooks/open-issues.sh` | всё, что сессия прочла | команды без вопроса человеку |
| Проверка зон и выкат | `scripts/protected-zones.mjs`, `.github/workflows/deploy.yml` | автор PR, запуск по кнопке | зона §7 без слова, непроверенный код на проде |
| Edge | `middleware.ts`, `lib/auth/public-api-routes.ts` | любой запрос | роут без входа |

## 2. Зацепки: что искать

Коды в скобках — по OWASP (Top 10:2025, LLM Top 10:2026, Agentic ASI): по ним
находку узнает и внешний читатель.

- **Подсунутый текст** (LLM01, ASI01). Тексты туристов, броней, issues, комментариев,
  страниц и выводов инструментов попадают к модели как указания? Вывод инструмента
  должен приходить в обёртке `wrapUntrustedBlock` из `lib/ai/untrusted.ts`.
- **Лишние права агента** (ASI02, ASI03). Пишущий инструмент решает по аргументу
  модели? Подтверждение читает код из слов человека и привязывает его к цели.
- **ПД за границу** (LLM02, 152-ФЗ). Имя, телефон, почта или координаты человека в
  промпте зарубежной модели без маски. Маски — `lib/security/pii-redact.ts`, очистка
  снимка — `lib/images/strip-metadata.ts`, ПД партнёру — только
  `lib/notifications/pd-alert.ts`. Подробно — скилл `pd-guard`.
- **Расход без предела** (LLM06). Анонимная дверь без суточного предела на адрес и
  своей доли бюджета (`lib/ai/anon-chat-guard.ts`), без потолка на размер вопроса,
  истории и число вызовов инструментов за ход.
- **Вывод модели как код** (LLM10). Ссылки и разметка в ответе
  (`lib/kuzmich/chat-links.ts`): своя ссылка ведёт только на свой сайт.
- **Витрина мимо правила** (§0). Туры и компании в выдаче, подсказке или ответе
  агенту мимо `publicTourSql` (`lib/tours/public-visibility.ts`) и `publicPartnerSql`.
  Подробно — скилл `vedar-honesty`.
- **Обход своих проверок.** Edge-гвард, реестр публичных API, проверка зон, рука,
  права сессий, сторожа в тестах. Подробно — раздел 3.
- **Цепочка поставки агентов** (ASI04). Сторонние скиллы и хуки, команды без вопроса,
  неприколоченные версии в workflow.

## 3. Опровержение: дыра в собственной проверке

Главный урок прогона 26.11: исправление само становится дырой, если проверка решает
не по тем данным. Шесть образцов — каждый нашло ревью безопасности на PR с
исправлением. Перед тем как назвать проверку надёжной, примерь к ней все шесть.

1. **Решает по данным, которые пишет атакующий.** Дневные пределы A2A и виджета
   пропускали вопрос о беде, а признак беды — слово «sos» в тексте клиента (#3837).
   Пределы теперь считают каждый вопрос; сверх предела вопрос о беде получает готовый
   блок 112 без модели. Сторож — `tests/unit/a2a-chat-door-limits.test.ts`.
2. **Чистит по списку запрещённого.** JPEG копировался как есть после начала данных:
   EXIF после конца кадра и второй кадр телефона уносили координаты; GIF шёл без
   разбора (#3840). Теперь остаётся только известное безопасное, хвост отбрасывается,
   непонятное — отказ. Сторож — `tests/unit/vision-strips-metadata.test.ts`.
3. **Ловит одну форму записи.** Маска имени срабатывала только на имени с большой
   буквы после пробела: «меня зовут иван», «МЕНЯ ЗОВУТ ИВАН», «Меня зовут: Иван»
   проходили (#3840). Сторож — `tests/unit/turn-pd-mask.test.ts`.
4. **Видит намерение, но не цель.** Слово «скрой» где угодно в сообщении оператора
   открывало снятие любого его тура: модель, подученная текстом туриста, выбирала тур
   сама (#3843). Теперь глагол без отрицания и тур — в одной фразе. Сторож —
   `tests/unit/price-move-guardrail.test.ts`.
5. **«Только чтение», которое исполняет и пишет.** Без вопроса стояли `git fetch`
   (`--upload-pack` исполняет команду) и `git log` (`--output` пишет файл с текстом
   из `--format`) (#3845). Без вопроса теперь только `git status`. Сторож —
   `tests/unit/claude-settings-permissions.test.ts`.
6. **Сторож зелёный не потому.** Сцена на базе ждала тестовые туры в первых десяти
   строках, а в базе CI их вытеснили живые туры; на первой голове PR она прошла
   случайно (#3840). Сцена теперь сама кладёт чужие строки и гасит их на своё время —
   `tests/integration/public-tour-gate.pg.test.ts`.

Как пробовать обход: другой регистр, разделитель и число пробелов; другой формат
файла и данные после его конца; та же просьба в другом поле или другой фразе;
отрицание за два-три слова от глагола; флаги «безопасной» команды; другой порядок
строк в базе.

## 4. Оценка

- **Высокая:** чужой кабинет, деньги, SOS и контроль выхода, ПД многих людей,
  исполнение кода.
- **Средняя:** дыра в собственной проверке (правило 1 в `.github/security-review-rules.md`),
  ПД одного человека за границу, Кузьмич замолкает для всех, витрина мимо §0.
- **Низкая:** нужен доступ, который уже даёт больше, или вред ограничен одним
  запросом.

Сомнение в оценке называется словами, а не округляется вниз.

## 5. Отчёт владельцу

По CLAUDE.md §5.2. Главное — в первых фразах: сколько находок, какие опасны, что
предлагается. Каждая находка — номер, место `file:line`, путь атаки одной фразой,
вред, исправление. Отдельно — что проверено и чем. Вопрос владельцу — с вариантами
под номерами. Отчёт кончается строкой «Не проверено:».

## 6. Исправление — по слову владельца

- Один PR на тему. Сторож судит поведение — вызов, рендер, сцену на настоящей базе
  (CLAUDE.md §4, скилл `vedar-code-rules`), а каждая строка защиты проверяется
  мутацией (`scripts/session/mutate.mjs`).
- Ревью безопасности на PR читает `.github/security-review-rules.md`. Его находку
  проверяешь по коду и чинишь в том же PR, до влития.
- Зоны §7 — скилл `vedar-protected-zones`, ПД — `pd-guard`, деньги — `money-path`,
  ход PR до влития — `pr-drive`.

Принципы, которые закрыли все шесть образцов из раздела 3:
- решение принимает код по данным, которых атакующий не пишет;
- оставляется известное безопасное, а не вырезается известное опасное;
- намерение человека привязано к цели — к туру, к цене, к фразе;
- «не знаю» не равно «можно»: отказ с причиной, а не пропуск;
- там, где модель звать нельзя, человек получает детерминированный ответ (блок 112),
  а не молчание.
