# mcp-kamchatka-data — архив (04.09.2026)

Отдельный stdio-сервер MCP «kamchatka-data-ingestion»: три источника
(Telegram МЧС, локальные сообщества VK, база туризма) через `axios` +
`cheerio`, оболочка на `@modelcontextprotocol/sdk` и `@anthropic-ai/sdk`.

**Почему в архиве.** Ни одна из четырёх зависимостей не стоит в
`package.json`, то есть в этом репозитории код не собирался и не запускался
никогда; из живого кода его никто не импортирует. При этом `lib/mcp` целиком
был исключён из `tsconfig`, чтобы эти четыре файла не краснели, — и заодно
без проверки типов оставались файлы публичного MCP-сервера `/api/mcp`, которые
никто не импортирует. Исключение снято, каталог перенесён сюда.

**Что здесь ценного.** `sources/source-result.ts` и сторож
`mcp-source-refusal.test.ts` — запись урока #1494 (01.09): источник обязан
уметь сказать «не смог», и третий исход должен жить в ТИПЕ, а не только в
логе. Правило действует для всего репозитория (CLAUDE.md §4.0); сам код
хранится как образец, тест из прогона снят вместе с ним.

Вернуть в дерево можно только вместе с зависимостями и собственным
`package.json` как отдельный пакет.
