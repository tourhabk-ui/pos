# AI-релей на VPS

Хоп **вне Cloudflare** для флагманских моделей. Нужен потому, что
Cloudflare-воркер (`infra/ai-relay/`) задачу не решает — см. «Почему не
воркер» ниже.

## Что это даёт

| | сейчас | с релеем |
|---|---|---|
| OpenRouter (Claude/GPT) с прода | 403 | доступен |
| Anthropic напрямую с прода | 403 | доступен |
| Код платформы | — | **не меняется** |

Меняются только переменные окружения приложения на Timeweb.

## Что арендовать

Любой VPS **за пределами РФ**, минимальный тариф. Нагрузка — единицы
запросов в сутки от агентов эволюции; ни ядер, ни памяти это не требует.
Нужны: публичный IP, домен (для TLS) и Node 18+.

Проверьте перед покупкой, что с этого хоста `openrouter.ai` отвечает:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://openrouter.ai/api/v1/models
```

Ожидается `200`. Если `403` — площадка блокируется так же, как мы, и
брать её незачем. **Это единственная проверка, которая тут что-то
доказывает**: остальное можно настроить, а отказ апстрима — нельзя.

## Установка

```bash
# 1. Код
mkdir -p /opt/ai-relay && cd /opt/ai-relay
# скопировать сюда server.js из этой папки

# 2. Секрет — длинный и случайный, он единственная защита порта
openssl rand -hex 32   # запомнить: пойдёт и на VPS, и в Timeweb

# 3. Служба
cat > /etc/systemd/system/ai-relay.service <<'UNIT'
[Unit]
Description=Vedar AI relay
After=network.target

[Service]
ExecStart=/usr/bin/node /opt/ai-relay/server.js
Environment=PORT=8080
Environment=RELAY_SECRET=ЗАМЕНИТЬ_НА_СЕКРЕТ
Restart=always
RestartSec=5
User=nobody
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
UNIT

systemctl enable --now ai-relay
```

Служба **не стартует без `RELAY_SECRET`** — это сделано намеренно.
Открытый релей к LLM означает чужие запросы под нашим адресом; молчаливый
запуск без секрета был бы тем случаем, когда «работает» и «безопасно»
расходятся.

## TLS

Прод ходит по HTTPS, значит нужен сертификат. Проще всего Caddy — он
получает и продлевает его сам:

```
relay.ВАШ-ДОМЕН {
    reverse_proxy localhost:8080
}
```

Без домена и TLS **не разворачивать**: заголовок `Authorization` с ключом
OpenRouter пойдёт по открытому каналу.

## Переменные на Timeweb

```
OPENROUTER_BASE_URL = https://relay.ВАШ-ДОМЕН/or/api/v1
ANTHROPIC_BASE_URL  = https://relay.ВАШ-ДОМЕН/anthropic
GITHUB_PROXY_BASE   = https://relay.ВАШ-ДОМЕН        (без хвостового /)
```

Секрет прод передаёт заголовком `X-Relay-Secret`. **Проверьте, что
вызывающий код его шлёт** — у воркера проверка секрета была опциональной,
здесь она обязательна, и без заголовка релей ответит `403 forbidden`. Это
отличается от прежнего 403 текстом: `{"error":"forbidden"}` наш,
`{"success":false,"error":"Access denied by security policy."}` — чужой.

## Приёмка

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  -H "X-Relay-Secret: ВАШ_СЕКРЕТ" \
  https://relay.ВАШ-ДОМЕН/or/api/v1/models      # ожидается 200

curl -s -o /dev/null -w '%{http_code}\n' \
  https://relay.ВАШ-ДОМЕН/or/api/v1/models      # без секрета — ожидается 403
```

Второй вызов важен не меньше первого: он доказывает, что порт закрыт.

Затем — `GET /api/cron/health` с прода: `ai.openrouter` обязан стать
`true`. До этого момента считать, что заработало, нельзя: проверка с
вашей машины ничего не говорит о проде, а весь этот разбор начался ровно
с того, что путь работал снаружи и не работал изнутри.

## Реестр провайдеров (152-ФЗ)

Хост релея — **новый приёмник персональных данных**, даже если он только
пересылает. Внести в `lib/agents/compliance/provider-registry.ts` с
фактической юрисдикцией VPS:

```ts
{ host: 'relay.ВАШ-ДОМЕН', jurisdiction: 'ГДЕ АРЕНДОВАН',
  domestic: false, provider: 'Свой релей (хоп к OpenRouter/Anthropic)' },
```

`domestic: false`, если VPS вне РФ — а он вне РФ по построению. То есть
трансграничная передача этим не снимается, и `redactPII` перед промптом
по-прежнему обязателен. Релей чинит ДОСТУПНОСТЬ, а не юрисдикцию.

## Почему не воркер

Cloudflare-воркер написан верно и работает: с раннера GitHub он проксирует
OpenRouter и отдаёт 200 (проба 168, 690 КБ). Но с прода на Timeweb тот же
релей отдаёт 403 — и телом, которого сам воркер выдать не может.

Блокировка следует **за звонящим, а не за путём**. Ведущее объяснение:
OpenRouter стоит за Cloudflare, и субзапрос воркера к Cloudflare-хосту
доносит наверх `CF-Connecting-IP` исходного клиента. Воркер вырезает этот
заголовок в коде, но подставляется он на edge — ниже уровня, где
выполняется наш код.

Отсюда правило, которое стоит помнить: **воркер Cloudflare не спрячет
клиента от апстрима, который сам за Cloudflare.** Нужен хоп вне их сети.
