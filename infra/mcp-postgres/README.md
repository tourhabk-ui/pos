# Чтение БД из MCP: как включить

Зачем. Чтобы узнать факт о проде, приходилось писать cron-эндпоинт, мержить,
ждать деплой и читать логи прогона — на один вопрос уходило от двадцати минут
до часа. Так добывались и «8 живых туров из 20 обещанных», и разбор немоты
DeepSeek 04.09. Прямое чтение превращает это в один запрос.

Наш собственный хук `.claude/hooks/db-schema-check.sh` уже написан в расчёте
на этот инструмент: он печатает «Проверил колонки через MCP postgres query?».
До сих пор проверять было нечем.

## Порядок

**1. Завести роль (один раз, в psql от владельца базы).**

```bash
psql "$DATABASE_URL" -v mcp_password="'ПРИДУМАЙТЕ_ПАРОЛЬ'" -f infra/mcp-postgres/role.sql
```

Скрипт выдаёт `SELECT` только на перечисленные в нём таблицы и не трогает
умолчания, поэтому таблица, заведённая завтра, роли не откроется.

**2. Проверить границы (тем же psql).**

```sql
SET ROLE mcp_readonly;
SELECT count(*) FROM places;   -- отвечает
SELECT count(*) FROM users;    -- отказ: permission denied
DELETE FROM places;            -- отказ: permission denied
RESET ROLE;
```

Если первый запрос упал, а второй прошёл — роль настроена наоборот, и её
нельзя использовать.

**3. Подключить клиента — ВНЕ репозитория.**

```bash
claude mcp add postgres -- npx -y @modelcontextprotocol/server-postgres \
  "postgresql://mcp_readonly:ПАРОЛЬ@ХОСТ:5432/БАЗА?sslmode=require"
```

Файла `.mcp.json` в корне проекта быть НЕ должно, и это не забывчивость.
Платформа сама отдаёт MCP-манифест по адресу `/.well-known/mcp.json`, и два
файла с почти одинаковым именем — один наш серверный, другой клиентский —
путали читателя; запрет держать клиентский конфиг в репозитории записан
решением ревью («замечание 4») и сторожится
`tests/unit/mcp-phone-dedup.test.ts`. Я предложил обратное, пока не увидел
этой записи, — правило старше и остаётся в силе.

Практическое следствие: набор серверов у каждой машины свой. Это цена
решения, а не недосмотр.

## Что даёт гарантию

Гарантия — **роль в базе**, а не сервер MCP. Официальный
`@modelcontextprotocol/server-postgres` обещает выполнять запросы в READ ONLY
транзакции, но помечен в npm как «no longer supported», и опираться на
обещание неподдерживаемого клиента там, где лежат чужие персональные данные,
нельзя. Роль без права записи и без доступа к таблицам с ПД держит границу
независимо от того, что попросит клиент и какую версию сервера подставят.

## Чего этим инструментом делать нельзя

- **Тянуть персональные данные в переписку.** Роль до них не дотягивается по
  построению, и обходить это выдачей новых грантов «на минутку» нельзя: весь
  диалог уходит зарубежной модели, то есть это трансграничная передача ПД
  (152-ФЗ, CLAUDE.md §8).
- **Считать прочитанное вечной правдой.** Цифра из базы — снимок момента.
  Числа, которые живут в документации, обязаны нести дату замера: правило
  появилось после «778 мест» и «20 туров», простоявших в CLAUDE.md месяцами
  при реальных 379 и 8.
