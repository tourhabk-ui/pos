# KML-инбокс — треки сообщества

Сюда кладутся `.kml` с треками (выгрузки idilesom, телеграм-каналы карт,
GPX/KML от гидов и операторов, конвертированные в KML). Любой пуш в main,
меняющий эту папку, запускает `data-kml-inbox.yml`: файлы постятся на
прод-эндпоинт `/api/cron/kml-inbox`.

Правила честности импорта (`lib/import/kml-inbox.ts`):

- привязка ТОЛЬКО по совпадению нормализованного имени — привязка по
  близости удалена (из 290 её привязок проверку выдержала 31);
- настоящие треки (osm, visitkamchatka, немаркированные) не перетираются —
  community-трек ложится только поверх пустоты, синтетики или прежнего
  kml_inbox;
- нет совпадения имени — маршрут создаётся СКРЫТЫМ, в очередь на ревью;
- автор трека сохраняется в metadata (атрибуция), в LLM не уходит.

Импорт идемпотентен: повторный прогон по уже обработанным файлам ничего
не ломает. Перезапустить обработку всей папки можно любой правкой в ней —
в том числе этого файла.

## Инбокс — лоток, не архив (урок 20.08)

Папка переигрывается ЦЕЛИКОМ каждым пушем. Пока цели файлов жили,
повтор был идемпотентен (kept/imported); слияния и переименования
20.08 это сломали: vodopad-spokoynyy.kml пересоздал скрытого дубля
(живая тёзка переименована), ozero-tolmachevo.kml налил трек в
скрытую запись (живая слита, ё/е-нормализация не покрывает о/а).

Правило: обработанный файл — удалять тем же коммитом, что читает
итог прогона. История остаётся в git; папка держит только то, что
ещё не доехало.
