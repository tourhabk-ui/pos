# Китай: как Ведару появиться у китайских моделей и агентов — пошагово для владельца

> Снято 13.10.2026. Повод — слово владельца: «в MCP и A2A ни одна китайская модель
> не зашла ни разу — мы для них не существуем, а должны быть». Внешние процедуры
> сверены с документацией площадок 13.10 (ссылки в шагах); интерфейсы меняются,
> при расхождении верить экрану, а не этому файлу. Общий чек-лист каталогов —
> `CATALOGS.md`, этот файл — только китайский контур.

## Почему ноль: три факта

1. **Модели о нас не знают.** Проба 12.10 с прода, без поиска
   (`GET /api/cron/model-knowledge-probe`, прогон 1): DeepSeek — не знает, Qwen
   (qwen3.8-max) — «不知道», Kimi и GLM спросить нечем — на Timeweb нет
   `MOONSHOT_API_KEY` и `GLM_API_KEY`. В обучающие данные модели не записаться;
   управлять можно только тем, что модель видит в момент ответа: поиском и
   каталогами.
2. **В китайские каталоги мы не поданы ни в один.** ModelScope MCP广场, Coze, mcp.so,
   Baidu и Bing Webmaster требуют аккаунта, а аккаунт из репозитория не заводится.
   Стоим только в официальном реестре MCP, Smithery, Glama и a2aregistry.org —
   китайские разработчики их почти не смотрят.
3. **Журнал не отличил бы китайского агента, даже если он пришёл.** Модель не пишется
   нигде: MCP записывает `clientInfo.name` из `initialize`, A2A — самоназвание из
   User-Agent, страны и языка нет. В словаре семейств клиентов (`ua_family`) нет ни
   одного китайского: Qwen Code, Cherry Studio, Dify, Trae, Lingma, Kimi, Doubao,
   Coze уходят в «неизвестен». За 30 дней к 12.10 таких «неизвестен» было 173 из
   1085 внешних вызовов (перепись `mcp-census`, run 112). «Ни разу» — отчасти
   «не видим». Это чинится из репозитория (шаг 0).

Ещё два пробела из репозитория: подтверждения владения сайтом стоят только для Google
и Яндекса (`app/layout.tsx`, `verification`), Baidu и Bing не подтверждены; китайская
HTML-страница одна — `/zh`, и названия туров на ней русские.

## Шаги для вас — по убыванию отдачи

### Шаг 1. ModelScope MCP广场 (魔搭) — главный китайский каталог MCP, экосистема Qwen

Факты 13.10: запись создаётся по URL с типом `streamable_http` без кода; вход возможен
через GitHub или телефон; два режима публикации — «可托管部署» (платформа сама
проверяет доступность и `tools/list`) и «仅分发展示» (только показ); для режима
хостинга сервер должен отвечать на `tools/list` без авторизации — наш отвечает.
Источники: [MCP广场 — как внести свой сервис](https://www.modelscope.cn/headlines/article/1189),
[issue modelscope#1809 о внешнем Streamable HTTP](https://github.com/modelscope/modelscope/issues/1809).

1. https://modelscope.cn → 登录 → войти через GitHub (телефон КНР для входа не нужен;
   он нужен для 实名 и бесплатных квот API, подаче сервиса это не мешает — если экран
   потребует иначе, скажите).
2. https://modelscope.cn/mcp → «创建MCP服务» (自主创建).
3. Поля:
   - 名称: `Vedar（维达尔）— 堪察加旅游平台`
   - 英文名 / ID: `vedar-kamchatka`
   - 简介 (одна строка): `俄罗斯堪察加半岛旅游平台：本地旅行社的团队游及真实余位、火山与地震预警、地点与路线、住宿、租赁、交通、天气、行程规划。无需认证。`
   - 描述 / README: текст из раздела «Тексты» ниже (китайский + английская строка).
   - MCP Server Config:
     ```json
     {"mcpServers":{"vedar":{"type":"streamable_http","url":"https://vedarai.ru/api/mcp"}}}
     ```
   - 标签: 旅游, 生活服务 (и 地图/位置, если есть).
   - 发布方式: «可托管部署». Если проверка не прошла — «仅分发展示» и пришлите мне текст
     ошибки (у платформы три этапа: разбор конфигурации → доступность → подключение к
     MCP).
4. Подача из формы обрабатывается до 3 рабочих дней (по справке площадки).
5. Как увижу: в `/hub/admin/a2a` → «Кто читает визитки и манифесты» появится семейство
   ModelScope (после шага 0), в «По MCP» — клиент площадки.

### Шаг 2. mcp.so — каталог, которым пользуются китайские разработчики (двуязычный)

1. https://mcp.so/submit → Sign In (GitHub).
2. Вкладка «Remote Server» (если нет — «MCP Server»). Поля: Name `Vedar — Kamchatka travel`,
   Repository URL `https://github.com/tourhabk-ui/pos` (репозиторий публичный, README
   описывает MCP), адрес сервера `https://vedarai.ru/api/mcp`, описание — английская
   строка из `CATALOGS.md`, раздел «Одна строка».
3. Бесплатная подача идёт через модерацию; платная (39 $ единоразово) публикуется сразу
   со значком Verified — решение ваше.

### Шаг 3. Coze (扣子) — агенты на Doubao

Источник: [документация «基于 MCP 服务创建插件»](https://docs.coze.cn/guides_create_a_plugin_based_on_mcp).
Плагин типа MCP принимает HTTPS-адрес (домен, не IP), заголовки и способ авторизации, в
том числе «不需要授权»; инструменты подтягиваются сами.

1. https://www.coze.cn → аккаунт. Регистрация по телефону; примет ли номер не КНР —
   проверяется только на месте. Не примет — шаг ждёт номера КНР (coze.com для
   иностранцев есть, но китайская аудитория на coze.cn).
2. Рабочее пространство → 资源库 → «+资源» → 插件 → 类型: MCP.
3. 插件 URL: `https://vedarai.ru/api/mcp`; Header 列表: пусто; 授权方式: 不需要授权 → 确认.
4. 试运行: инструмент `get_tours` без параметров — в Response список туров.
5. 发布 → затем «扣子插件商店» (публичный магазин плагинов) по его руководству.

### Шаг 4. Baidu 搜索资源平台 — чтобы нас видел поиск Baidu и модели на нём (文心 и другие)

Источник: [справка по верификации сайта в Baidu](https://help.aliyun.com/zh/swbs/user-guide/verify-a-website-on-baidu-webmaster-platform).
Индексация после подачи — 4–8 недель; ICP-регистрация нужна только для хостинга в КНР,
нам нет.

1. https://ziyuan.baidu.com → вход с аккаунтом Baidu (регистрация по телефону; примет ли
   номер не КНР — проверяется на месте).
2. 用户中心 → 站点管理 → 添加网站 → `https://vedarai.ru` (с https) → 站点属性: 旅游.
3. 验证方式: HTML标签验证 → скопируйте значение `content="…"` метатега
   `baidu-site-verification` → пришлите мне → я добавлю тег на сайт (шаг 4б) → нажмите 完成验证.
4. После верификации: 资源提交 → sitemap `https://vedarai.ru/sitemap.xml`;
   普通收录 → API推送 → скопируйте `token=…` из адреса push → пришлите мне → я подключу push
   новых страниц (как IndexNow).

### Шаг 5. Bing Webmaster — Bing работает в КНР, и часть китайских ИИ-поисков опирается на него

1. https://www.bing.com/webmasters → вход с аккаунтом Microsoft (почта).
2. Add a site → `https://vedarai.ru` → способ: HTML Meta Tag → значение `msvalidate.01` →
   пришлите мне (шаг 5б) → Verify. Есть Google Search Console — можно импортировать сайт
   из него одной кнопкой вместо тега.
3. Sitemaps → `https://vedarai.ru/sitemap.xml`. IndexNow уже стоит: ключ по адресу
   `/indexnow.txt`, пинги идут в `yandex.com/indexnow` и по протоколу расходятся всем
   участникам, Bing в том числе; Baidu в IndexNow не участвует, для него — шаг 4.

### Шаг 6. Ключи Kimi и GLM — чтобы проба знания спрашивала всех четверых

- Zhipu (GLM): https://open.bigmodel.cn (код ходит на `open.bigmodel.cn`) → API key →

### Шаг 7. Китайский контент — решение

`/zh` есть, но названия туров на нём русские. Чтобы китайский поиск цитировал нас на
«堪察加 旅游 火山», нужны китайские страницы: карточки туров, два-три десятка главных мест,
страница безопасности. Варианты:

- **(а)** перевод Qwen с вашей вычиткой, хранить в базе рядом с русским (`title_zh`,
  `description_zh`), страницы `/zh/tours/<slug>` и `/zh/places/<id>` с hreflang — делаю
  по слову «го»;
- **(б)** не делать: тогда китайские чаты найдут нас только как MCP-сервер, не как сайт.

Что цитируют китайские ИИ-чаты (обзоры GEO 08–09.2026, мнения авторов, не замер):
Doubao — контент экосистемы Toutiao и новостные источники; DeepSeek — структурированные
данные и документы с цифрами; Kimi — свежие оригинальные длинные тексты; Qwen —
официальные сайты. Посты на 头条号 и 知乎 — маркетинг вне репозитория.

## Как увидим результат

- `/hub/admin/a2a`: «По MCP» — клиенты, которые хотя бы поздоровались; «Кто читает визитки
  и манифесты» — семейства краулеров, после шага 0 с меткой «КНР». `/hub/admin/mcp` —
  «Кто звал».
- Переписи только для чтения: `GET /api/cron/agent-entry-census` (краулеры по семействам,
  китайские отдельной строкой), `GET /api/cron/mcp-census?days=30` (клиенты). Запускаю
  через prod-check после каждого вашего шага.
- Проба знания — ежемесячно; первое «знает» появится, когда модель с поиском найдёт `/zh`.

Чего измерить нельзя из репозитория: доступность vedarai.ru из КНР (нет точки в Китае)
и индексацию в Baidu и Bing (оба отвечают раннеру капчей) — это видно только в их
вебмастерах после шагов 4–5.
