## Цель (слово владельца 16.10)

«Цель — не „подключить как можно больше моделей“, а чтобы турист, который
планирует Камчатку через ИИ-ассистента, получал в ответе Ведар и верные данные.
Глубже, не шире: новых фич и каналов не добавляй.»

## Критерии успеха

Проверка — через 8 недель после базового замера (56 дней от первого дня
базы, допуск ±3 дня), повтором того же замера тем же скриптом. Каждый критерий имеет три исхода: выполнен, не выполнен,
**не смог проверить** (данных нет). Третий не засчитывается как первый (§4.0).

| № | Критерий (слова владельца) | Как считается |
|---|---|---|
| К1 | «нижняя граница доли ответов с vedarai.ru выше базовой минимум в двух ассистентах» | Для каждого ассистента: нижняя граница 95% интервала Уилсона доли ответов с vedarai.ru на 8-й неделе **больше точечной доли базового замера**. Выполнен, если так у двух ассистентов или больше. |
| К2 | «а у конкурентов такого же роста нет» | Для каждого ассистента, засчитанного в К1, то же правило для каждого конкурента. Если у конкурента в том же ассистенте рост по тому же правилу есть — этот ассистент из К1 вычёркивается: вырос весь поиск по Камчатке, а не мы. |
| К3 | «в отчётах Bing AI Performance и Яндекса появились цитаты Ведара» | Число цитат/показов vedarai.ru в выгрузке Bing AI Performance и в «Видимости в Алисе AI» Вебмастера больше нуля при нуле в базовой выгрузке. Нет базовой выгрузки — «не смог проверить», а не «выполнен». |
| К4 | «в журналах есть вызовы MCP минимум от двух внешних семейств клиентов с подтверждённым происхождением» | Семейство — вендор клиента (Anthropic, OpenAI, Google, …). «Подтверждённое» — адрес запроса попал в опубликованные вендором диапазоны исходящих адресов или прошёл обратный и прямой DNS вендора. Самоназвание клиента (`clientInfo.name`, User-Agent) — не подтверждение. Свои вызовы исключены (`MCP_SELF_TAG`). |
| К5 | «есть хотя бы одна заявка с ИИ-реферером» | Заявка, у которой первый заход на сайт пришёл с адреса ассистента (chatgpt.com, perplexity.ai, gemini.google.com, copilot.microsoft.com, alice.yandex.ru, …) или с меткой `utm_source` ассистента, либо заявка через MCP от подтверждённого по К4 семейства. |

## Что такое «ответ с vedarai.ru»

- **Засчитывается:** домен `vedarai.ru` (с поддоменами) в тексте ответа или
  среди источников ответа (`url_citation` и аналоги у каждого API).
- **Не засчитывается, но пишется отдельно:** имя «Ведар» / «Vedar» без домена;
  зеркала нашего кода и текстов на чужих доменах (16.10 ChatGPT процитировал
  odel.app — копию нашего репозитория на GitHub). Это сигнал, а не наш ответ:
  турист по нему к нам не приходит.
- **«Верные данные»** — отдельная оценка по ответам, где Ведар есть: факт из
  ответа сверяется с базой (цена, оператор, сезон, телефон 112). Расхождение —
  находка, а не «упоминание засчитано».

## Конкуренты — по данным выдачи, не по памяти

Правило записано до замера: после базового замера берутся домены, которые
ассистенты цитируют в ответах на вопросы о турах, датах и ценах; ранжируются
по числу ответов с цитатой по всем ассистентам вместе; конкурент — первые три
домена, которые продают или собирают туры по Камчатке. Государственные и
научные источники (МЧС, KVERT, парки) — не конкуренты: это источники фактов.
Выбранные три домена с причиной записываются сюда разделом «Конкуренты
базового замера» до повтора и больше не меняются.

## Замер

- **Вопросы.** 60–100 реальных вопросов туристов (RU/EN/ZH) из Яндекс
  Wordstat, отчётов запросов Вебмастера и Google Search Console; у каждого
  вопроса указан источник и намерение: планирование, безопасность, туры и
  даты, цены. Вопрос без источника в набор не входит. Файл вопросов
  фиксируется хэшем в первом прогоне; повтор идёт по тому же хэшу.
- **Ассистенты.** ChatGPT (OpenAI с поиском), Perplexity Sonar, Gemini с
  Google Search, Grok с поиском, YandexGPT. Ограничения названы заранее:
  - замеряется API с поиском, а не приложение: у приложения своя память,
    свой системный промпт и персонализация. Это ближайший воспроизводимый
    заменитель, а не ответ конкретному туристу;
  - у нашей ноги YandexGPT (Foundation Models API) поиска нет — она меряет
    знание модели, а не ответ с поиском. Генеративный ответ Search API Яндекса —
    отдельный продукт; ищет ли он по всему интернету, а не по заданным сайтам, —
    не проверено. Алиса меряется только выгрузкой «Видимость в Алисе AI»;
  - если поисковый движок вендора недоступен и запрос ушёл бы через чужой
    поиск (например, Exa вместо Google Search), нога записывается как «не
    измерено», а не подменяется.
- **Повторы.** Каждый вопрос — 5 раз в каждый из 3 разных дней.
- **Сырьё.** Каждый ответ сохраняется целиком с источниками, моделью,
  движком поиска, временем и ценой вызова в JSON (артефакт прогона).
- **Интервал.** 95% интервал Уилсона по ответам — как просил владелец.
  Повторы одного вопроса не независимы, поэтому рядом печатается тот же счёт
  по вопросам (доля вопросов, где Ведар был хотя бы в одном ответе). Если
  успех по ответам держится на одном-двух вопросах, отчёт говорит это прямо.
- **Известное свойство К1.** Если базовая доля у ассистента — ноль (а по
  пробе 16.10 на тематических вопросах с поиском нас нет ни у ChatGPT, ни у
  Grok), нижняя граница Уилсона больше нуля уже при одном попадании. Правило
  остаётся словами владельца; отчёт рядом с «выросли» всегда называет число
  попаданий и вопросов, чтобы одно попадание было видно как одно.

- Выгрузок Wordstat, Вебмастера (запросы, «Видимость в Алисе AI»), Google
  Search Console и Bing AI Performance у меня нет — их даёт владелец.
- Ключа Gemini с Google Search нет; через OpenRouter поиск Google не
  гарантирован.
- `agent_entry_hits` и журнал MCP не хранят адрес запроса — проверить
  происхождение по диапазонам вендоров нечем (К4 сегодня — «не смог
  проверить»).
- `MCP_SELF_TAG` не задан — свои вызовы в журнале MCP не отделены.
- Сырых access-логов Timeweb в доступных нам путях нет; есть ли они в

- Заявка не связана с заходом на сайт: `page_views` хранит реферер, но
  `leads` его не получает (кроме меток MCP-передачи), так что К5 сегодня
  проверяется только для заявок через MCP.
