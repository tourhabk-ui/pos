## Шаги для вас — по убыванию отдачи

### Шаг 1. Ключ Яндекса на Timeweb — сделан 14.10

Прогон 1 пробы агента (13.10, run 38410398226) ответил не 403, как
ожидалось, а `no_key`: на Timeweb не было ни `YANDEX_API_KEY`, ни
`YANDEX_FOLDER_ID`. То есть YandexGPT во втором эшелоне водопада молчал с
самого начала — нога числилась, ключа не было. Тот же `no_key` дала нога
`yandex` пробы знания (прогон 3).

14.10 владелец создал ключ в AI Studio кнопкой «Создать API-ключ» и положил на
Timeweb `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Сервисный аккаунт с ролями
`ai.editor`, `serverless.mcpGateways.invoker` и
`serverless.mcpGateways.anonymousInvoker` AI Studio создаёт при этом сама. Такой
ключ подходит и YandexGPT, и агенту с MCP, поэтому отдельный
`YANDEX_AGENT_API_KEY` не понадобился; переменная осталась на случай, если
агенту нужен будет свой ключ.

Дошли не с первого раза, и обе ошибки поучительны:

- **Прогон 4 пробы знания** — HTTP 400 «Specified folder ID 'aje…'». В
  `YANDEX_FOLDER_ID` лежал идентификатор ключа из окна его создания. Каталог
  начинается с `b1g`, ключ — с `aje`, организация — с `bpf`; верное значение —
  «…» в строке каталога `default` или адрес консоли после `/folders/`.
- **Прогон 5** — ключ и каталог приняты, YandexGPT ответил за 0,6 с, но
  заготовкой фильтра «Я не могу обсуждать эту тему. Давайте поговорим о
  чём-нибудь ещё.» со статусом `ALTERNATIVE_STATUS_CONTENT_FILTER`. Обёртка
  отдавала её текстом: проба записала «не знает», а во втором эшелоне
  водопада, где YandexGPT самый быстрый, заготовка ушла бы туристу ответом.
  С 14.10 это отказ с причиной `content_filter` в следе (сторож
  `yandex-content-filter`). Итоги — в маркере `model-knowledge-probe.json`.

### Шаг 2. Ведар в вашем MCP Hub — отложен решением владельца 14.10

Владелец 14.10: в MCP Hub Яндекса пока не добавляем — непонятная ценовая
политика. Проба агента `yandex-mcp-probe` ходит через тот же MCP-шлюз Яндекса
(ключу нужно право `yc.serverless.mcpGateways.invoke`), поэтому её маркер тоже
не поднимается, пока цена не ясна. Итог её прогона 1 записан выше, а не в
маркере: правка маркера запустила бы пробу.

Шаги ниже — на случай, когда решение будет.

Публичного каталога MCP у Яндекса на 13.10 нет: шаблоны MCP Hub — партнёрские,
внешний сервер добавляется в свой каталог. Это даёт Ведар всем вашим агентам в
AI Studio и Realtime API (голос), а заодно — проверку руками.

1. AI Studio → каталог → слева **Agent Atelier → MCP-серверы** → **Создать
   MCP-сервер → Внешний MCP-сервер**.
2. Имя `vedar` (3–63 знака, строчные латиница, цифры, дефис). Описание по
   желанию. «Сделать публичным» — только если хотите, чтобы любой агент
   облака ходил к нему без авторизации (сервер и так открыт, вреда нет).
3. В окне подключения: URL `https://vedarai.ru/api/mcp`, транспорт
   **Streamable HTTP**, авторизация **Без авторизации** → **Подключить**.
4. В списке **Инструменты** отметьте все (у нас 20; лимит на сервер, по
   документации MCP Hub на 14.10, — 150) → **Сохранить**. Четыре из них пишут
   (`create_lead`, `create_booking_request`, `create_stay_request`,
   `request_charter`): заявка уходит живому оператору, владельцу жилья или
   перевозчику, поэтому в проверках агента заявок не просить.
5. Роли, которые нужны вашему аккаунту: `serverless.mcpGateways.editor` и
   `iam.serviceAccounts.user`.

После этого в `/hub/admin/mcp` должен появиться клиент с меткой «РФ» — и мы
узнаем точное имя шлюза Яндекса для реестра.

### Шаг 3. GigaChat — решение

Та же проба для GigaChat потребует учётной записи разработчика Сбера
(ключ авторизации GigaChat API) и отдельной обёртки под их формат функций —
мост не подойдёт. Каталога, где нас увидят пользователи GigaChat, нет; подключить
нас может разработчик у себя по README. Пока не решено — не делаю.

## Как увидим результат

- Сводка прогона `yandex-mcp-probe`: исход (позвала инструменты / ответила без
  них / спросить не удалось с причиной), имена вызванных инструментов, типы
  элементов ответа Яндекса, журнал за окно пробы с именем клиента и меткой.
- `/hub/admin/mcp` — «Кто звал»: клиент с меткой «РФ»; `/hub/admin/a2a` — то же
  у агентов. Перепись `GET /api/cron/mcp-census?days=30` — группа `clients_ru`.
- Проба знания (`model-knowledge-probe`): нога `yandex` — знает / не знает /
  спросить не удалось, по-русски.

Чего измерить нельзя из репозитория: знает ли о нас Алиса в своём продукте и
есть ли мы в выдаче Нейро — это видно только руками в самом продукте.
