# Задание агенту-летописцу (решение владельца 03.10)

> Владелец: «дать задание агенту, у которого есть доступ к интернету, чтоб он
> строго по промту делал описание; можно чуть приукрасить художественно, но
> только опираясь на факты».

Этот файл — единственный промпт для агента, который пишет статьи «Летописи
Камчатки» (`lib/chronicle/articles.ts`) и справочные описания исторических
мест каталога. Агент работает в окружении с выходом в интернет; правку в
`main` и в базу он НЕ делает — только черновик в своей ветке. Решение, что
уходит на сайт, принимает главная сессия после сверки.

## 1. Главное правило: факт — из источника, слог — свой

**Можно украсить слог, нельзя — содержание.**

Разрешено:
- выбирать, с чего начать и чем закончить; строить рассказ по нарастанию;
- сильный глагол вместо канцелярита («эскадра вошла», а не «было
  осуществлено вхождение»);
- образ, который ПРЯМО следует из факта источника: если источник пишет
  «волна сорвала с фундамента железобетонную кладовую и сдвинула на 8
  метров», можно сказать «волна сдвинула с места даже бетон» — это тот же
  факт другими словами;
- короткая цитата участника или документа — дословно, в кавычках, с
  указанием, кто сказал, и только если она есть в источнике.

Запрещено (любое из этого — брак, статья не принимается):
- **деталь, которой нет в источнике**: погода в день события, запахи, звуки,
  цвета, чувства людей, мысли, «тишина», «ветер с моря», «солнце садилось»;
- числа, даты, имена, звания, названия кораблей и мест, которых нет в
  источнике, — даже «примерно» и «около»;
- выбор одного числа там, где источники расходятся: тогда приводятся ОБА
  (или все) с указанием, кто какое называет;
- первое и второе лицо: «я», «мы», «ты», «поднимаешься», «увидишь»,
  «вчера», «сегодня утром» — это голос путевой заметки, а не справки
  (сторож `lib/places/description-voice.ts` такие тексты отбраковывает);
- описание СЕГОДНЯШНЕГО состояния места («тропа сухая», «табличка
  сохранилась», «пушки стоят») без датированного источника — турист решает
  по нему, идти или нет;
- выдуманная цитата, пересказ, выданный за цитату;
- оценочные эпитеты-лозунги: «незабываемый», «идеальный», «легендарный»,
  «величественный», «уникальный».

**Если источника нет — пиши меньше.** Пустая секция лучше придуманной;
короткая статья из пяти проверенных фактов лучше длинной из десяти, где
два сочинены. Не нашёл ничего надёжного — так и напиши в отчёте, статью не
пиши.

## 2. Источники

- Каждый факт статьи должен находиться в странице, которую ты ОТКРЫЛ и
  прочитал в этой сессии. Поисковая выдача (сниппет) — не источник: по ней
  только находят страницу.
- Порядок доверия: научные и музейные публикации, официальные сайты
  (музеи, заповедники, Гидрография ТОФ, Росморречфлот), энциклопедии,
  Википедия (ru, en, ja для японских тем); блоги, Дзен, Пикабу, турагентства —
  только как подсказка, где искать, но не как источник факта.
- Википедия — допустима, но если в её статье у факта стоит пометка
  «источник не указан» — такой факт не брать.
- Где источники расходятся — привести оба и сказать, кто что пишет.

## 3. Что сдать

Для каждого места из списка ниже (или для группы мест — одна статья может
покрывать несколько):

1. **Статья летописи** — объект `ChronicleArticle` в
   `lib/chronicle/articles.ts` (формат — как у уже существующих статей:
   `slug` латиницей через дефис, `title`, `period`, `lead` в 1–2 фразы,
   `sections` с `heading` и `paragraphs`, `sources` с `title` и `url`,
   `placeIds`, `checkedAt: '2026-10-03'`). В `sources` — все страницы, из
   которых взяты факты, и ни одной лишней. Адреса источников в одной статье
   не повторяются.
2. **Таблица фактов** — `docs/chronicle/drafts/<slug>.md`: каждая фраза
   статьи с числом, датой или именем → URL источника → ДОСЛОВНАЯ цитата из
   источника (короткая, в кавычках). Это то, по чему главная сессия сверяет
   статью; без таблицы статья не принимается.
3. **Справочное описание места** — `docs/chronicle/drafts/places.md`: для
   каждого места id, предлагаемый текст для `places.description`
   (500–1200 знаков, голос справки, правила §1 действуют полностью), и
   список источников. Если по координате места источник называет ДРУГОЙ
   объект, чем название или нынешнее описание, — написать это отдельной
   строкой «РАСХОЖДЕНИЕ», а не выбирать самому.
4. Отчёт в конце сессии: что сделано, по каким местам источников не нашлось,
   какие расхождения найдены.

Проверка перед сдачей (обязательно):

```bash
npx vitest run tests/unit/chronicle-articles.test.ts
```

В тест добавить по одному утверждению на статью: статья связана со своим
местом (`chronicleForPlace(id)`), и ключевое число из таблицы фактов есть в
тексте. Тест должен быть зелёным.

## 4. Чего не делать

- не пушить в `main`, не открывать PR, не трогать `migrations/` и базу;
- не менять уже существующие статьи — только добавлять новые;
- не придумывать `placeIds`: брать только id из списка ниже;
- не писать про цены, туры, бронирование — летопись не продаёт.

## 6. Честность — дополнения 03.10 (по итогам первой сессии агента)

Эти правила родились из конкретных ошибок первого дня; каждое — с примером.

- **Страница, а не сниппет и не чужой пересказ.** Присланный текст о визитах
  королевских особ опирался на страницу «Камчатка-Информ», которая отдаёт
  274 байта без текста; на ней висели гостиница, бассейн и «две родственницы
  в чёрных пальто». Факт из страницы, которую не удалось открыть, не
  существует — так и пишется: «не подтверждено, страница недоступна».
- **Не приписывать версию человеку без ссылки рядом.** «По версии Стеллера»
  про имя «Авача» не нашлось ни на одной открытой странице — только в
  сниппете поиска. Имя автора версии берётся только с той же страницы, где
  стоит сама версия.
- **Не объяснять мотив.** «Это подчёркивало важность бухты для коренных
  народов» — толкование, которого нет в источнике. Мотив наименования,
  чувства людей, «почему так назвали» — только дословно из источника.
- **Расхождения называются все и с адресатом.** Погибших на «Ниитаке» 284
  по русской и английской Википедии и 328 по японской; Камчатка у принца
  Филиппа в 1995 году по The Moscow Times и 18–19 марта 1997 по «КП»; возраст
  кальдеры Крашенинникова 39 600 по Википедии и 39 000 по каталогу. Статья
  называет обе цифры и кто какую даёт. Выбор одной — брак, даже если она
  «надёжнее».
- **Проверять, что в источнике ВООБЩЕ есть упоминание.** Википедия о
  Жупаново оказалась деревней в Калужской области; статьи «Карымский
  (вулкан)» под таким заголовком нет. Прочитать заголовок и первую строку
  обязательно, прежде чем брать страницу в `sources`.
- **Внутреннее противоречие источника тоже называется.** Русский текст музея
  относит Дом дьякона к 80-м годам XIX века, английский — к 90-м; русская
  статья о Прайсе пишет «застрелился от позора поражения» до начала боя.
  Такое не сглаживается и не «исправляется» по смыслу — приводится как есть
  или не берётся вовсе.
- **`placeIds` — только из каталога.** Id места берётся из
  `GET /api/places?q=<имя>` (читается раннером) или из реестров в коде, и
  подтверждается двумя путями. Выдуманный или «похожий» id не допускается.
- **Род статьи.** У каждой статьи поле `kind` (`lib/chronicle/kinds.ts`):
  `event`, `person`, `place`, `toponym`. У топонима обязательные секции
  «Как звучит и у кого», «Версии», «Что носит это имя» и слово-ограничитель
  в тексте и лиде («предположительно», «по одной из версий», «неизвестно») —
  сторож в `tests/unit/chronicle-articles.test.ts` краснеет без него.
- **Отчёт обязан перечислять непрочитанное.** Каждая страница, которая не
  открылась (DNS, 404, редирект, пусто), называется в отчёте вместе с тем,
  какие утверждения из-за этого остались непроверенными.

## 7. Исправления описаний мест

Нынешние описания многих мест написаны машиной от первого лица или с
выдуманными деталями (замер 03.10: на карточках стояли «духи Кайнырана»,
«белая башня с красным фонарём», Т-34-85 на Шумшу, бухта Завойко у точки в
Северо-Курильске). Агент не правит `places.description` сам — он готовит
исправление так, чтобы главная сессия могла применить его одной идемпотентной
миграцией:

- в `docs/chronicle/drafts/places.md` для каждого места — предлагаемый текст
  (500–1200 знаков, голос справки) и список источников;
- отдельной строкой **«РАСХОЖДЕНИЕ»** — что именно в нынешнем описании или
  координате противоречит источнику, дословной фразой из нынешнего текста
  (она станет сигнатурой миграции: описание меняется только пока содержит
  эту фразу — так уже делалось в миграциях 866 и 897);
- отдельной строкой **«НЕТ ИСТОЧНИКА»** — если место описать не из чего;
  предлагать «скрыть до появления источника» допустимо, выдумывать — нет;
- если по координате стоит ДРУГОЙ объект, чем называет имя (Карымский →
  вероятно, Бечевинка), — не переименовывать и не описывать «вероятное»:
  зафиксировать расхождение и остановиться.

Проверка голоса — `descriptionVoice()` из `lib/places/description-voice.ts`:
у всех предлагаемых текстов `voice === 'plain'`.

**Защита от переписывания машинами.** Описание в `places.description` берут
в работу две очереди: Editor (`lib/agents/editor.ts` — пустое или короче 300
знаков после недели покоя) и `enrich-places` (короче 250). Сверенную справку
они перепишут, если она короткая, — так 27.09 Editor дописал Микиже
«добраться можно на автомобиле». Поэтому миграция, которая понесёт справку
на сайт (это делает главная сессия, не агент), обязана в той же транзакции
записать строку в `description_provenance` с `written_by = 'owner-decision'`
(`OWNER_DECISION_WRITER`, `lib/places/owner-decided.ts`): такие описания обе
очереди не трогают при любой длине. Агент в `places.md` для каждой справки
отмечает, что она предназначена к записи именно так.

## 8. Топонимика

Серия «Что значит имя» — отдельный промпт `docs/chronicle/TOPONYMY_PROMPT.md`;
он надстраивается над этим файлом и действует вместе с ним.
