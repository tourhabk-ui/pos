# Задание агенту-летописцу (решение владельца 03.10)

> Владелец: «дать задание агенту, у которого есть доступ к интернету, чтоб он
> строго по промту делал описание; можно чуть приукрасить художественно, но
> только опираясь на факты».

Этот файл — единственный промпт для агента, который пишет статьи «Летописи
Камчатки» (`lib/chronicle/articles.ts`) и справочные описания исторических
мест каталога. Агент работает в окружении с выходом в интернет; правку в
`main` и в базу он НЕ делает — только черновик в своей ветке. Решение, что
уходит на сайт, принимает главная сессия после сверки.

## 1. Главное правило: факт — из источника, слог — свой

**Можно украсить слог, нельзя — содержание.**

Разрешено:
- выбирать, с чего начать и чем закончить; строить рассказ по нарастанию;
- сильный глагол вместо канцелярита («эскадра вошла», а не «было
  осуществлено вхождение»);
- образ, который ПРЯМО следует из факта источника: если источник пишет
  «волна сорвала с фундамента железобетонную кладовую и сдвинула на 8
  метров», можно сказать «волна сдвинула с места даже бетон» — это тот же
  факт другими словами;
- короткая цитата участника или документа — дословно, в кавычках, с
  указанием, кто сказал, и только если она есть в источнике.

Запрещено (любое из этого — брак, статья не принимается):
- **деталь, которой нет в источнике**: погода в день события, запахи, звуки,
  цвета, чувства людей, мысли, «тишина», «ветер с моря», «солнце садилось»;
- числа, даты, имена, звания, названия кораблей и мест, которых нет в
  источнике, — даже «примерно» и «около»;
- выбор одного числа там, где источники расходятся: тогда приводятся ОБА
  (или все) с указанием, кто какое называет;
- первое и второе лицо: «я», «мы», «ты», «поднимаешься», «увидишь»,
  «вчера», «сегодня утром» — это голос путевой заметки, а не справки
  (сторож `lib/places/description-voice.ts` такие тексты отбраковывает);
- описание СЕГОДНЯШНЕГО состояния места («тропа сухая», «табличка
  сохранилась», «пушки стоят») без датированного источника — турист решает
  по нему, идти или нет;
- выдуманная цитата, пересказ, выданный за цитату;
- оценочные эпитеты-лозунги: «незабываемый», «идеальный», «легендарный»,
  «величественный», «уникальный».

**Если источника нет — пиши меньше.** Пустая секция лучше придуманной;
короткая статья из пяти проверенных фактов лучше длинной из десяти, где
два сочинены. Не нашёл ничего надёжного — так и напиши в отчёте, статью не
пиши.

## 2. Источники

- Каждый факт статьи должен находиться в странице, которую ты ОТКРЫЛ и
  прочитал в этой сессии. Поисковая выдача (сниппет) — не источник: по ней
  только находят страницу.
- Порядок доверия: научные и музейные публикации, официальные сайты
  (музеи, заповедники, Гидрография ТОФ, Росморречфлот), энциклопедии,
  Википедия (ru, en, ja для японских тем); блоги, Дзен, Пикабу, турагентства —
  только как подсказка, где искать, но не как источник факта.
- Википедия — допустима, но если в её статье у факта стоит пометка
  «источник не указан» — такой факт не брать.
- Где источники расходятся — привести оба и сказать, кто что пишет.

## 3. Что сдать

Для каждого места из списка ниже (или для группы мест — одна статья может
покрывать несколько):

1. **Статья летописи** — объект `ChronicleArticle` в
   `lib/chronicle/articles.ts` (формат — как у уже существующих статей:
   `slug` латиницей через дефис, `title`, `period`, `lead` в 1–2 фразы,
   `sections` с `heading` и `paragraphs`, `sources` с `title` и `url`,
   `placeIds`, `checkedAt: '2026-10-03'`). В `sources` — все страницы, из
   которых взяты факты, и ни одной лишней. Адреса источников в одной статье
   не повторяются.
2. **Таблица фактов** — `docs/chronicle/drafts/<slug>.md`: каждая фраза
   статьи с числом, датой или именем → URL источника → ДОСЛОВНАЯ цитата из
   источника (короткая, в кавычках). Это то, по чему главная сессия сверяет
   статью; без таблицы статья не принимается.
3. **Справочное описание места** — `docs/chronicle/drafts/places.md`: для
   каждого места id, предлагаемый текст для `places.description`
   (500–1200 знаков, голос справки, правила §1 действуют полностью), и
   список источников. Если по координате места источник называет ДРУГОЙ
   объект, чем название или нынешнее описание, — написать это отдельной
   строкой «РАСХОЖДЕНИЕ», а не выбирать самому.
4. Отчёт в конце сессии: что сделано, по каким местам источников не нашлось,
   какие расхождения найдены.

Проверка перед сдачей (обязательно):

```bash
npx vitest run tests/unit/chronicle-articles.test.ts
```

В тест добавить по одному утверждению на статью: статья связана со своим
местом (`chronicleForPlace(id)`), и ключевое число из таблицы фактов есть в
тексте. Тест должен быть зелёным.

## 4. Чего не делать

- не пушить в `main`, не открывать PR, не трогать `migrations/` и базу;
- не менять уже существующие статьи — только добавлять новые;
- не придумывать `placeIds`: брать только id из списка ниже;
- не писать про цены, туры, бронирование — летопись не продаёт.
