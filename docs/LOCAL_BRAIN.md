# Своя модель на своём железе — проба

> Владелец 22.10: «проще на своём железе поднять, завтра посмотрю, есть у меня мощный комп, вместе настроим».
> Общий план — `docs/OWN_BRAIN_PLAN.md`. Эта памятка — про первый шаг на домашнем компьютере.

## 1. Что проверяем

Может ли открытая модель на вашем компьютере отвечать как Кузьмич:
- не давать опасных советов и не отказывать на законных вопросах туриста;
- брать цены и факты из инструментов Ведара, а не придумывать;
- отвечать не медленнее живого Кузьмича.

Сайт и живой Кузьмич при этом не меняются. Модель ходит за фактами в публичный MCP `vedarai.ru`, только в читающие инструменты: заявок проба не создаёт. Вопросы — эталонные из еженедельного эвала, персональных данных в них нет.

## 2. Какой у вас компьютер

Нужна память видеокарты.
- Windows: Диспетчер задач → Производительность → ГП → «Выделенная память GPU».
- Или в терминале: `nvidia-smi` (строка с `MiB`).

Ориентир по модели (4-битная сборка; точное имя смотрим на ollama.com/library в день установки):

| Память видеокарты | Размер модели | Что ждать |
|---|---|---|
| 24 ГБ и больше | 27–35B (Qwen3 или новее) | главный кандидат пробы |
| 16 ГБ | около 14B | может пройти безопасность, факты — под вопросом |
| 8–12 ГБ | 7–8B | для Кузьмича, скорее всего, слабо; для проверки установки годится |

Модель, которая не влезает в видеокарту, частично уходит в обычную память и работает в разы медленнее. Это видно в итоге пробы по скорости.

## 3. Установка Ollama

1. Скачать с ollama.com/download и установить.
2. **Окно контекста — до первого запуска модели.** По умолчанию у Ollama 4096 токенов. Промпт Кузьмича около 12 тысяч знаков плюс описания инструментов, и Ollama молча срежет начало: модель ответит без правил Кузьмича, и проба покажет «слабую модель» там, где дело в настройке.
   - Windows: закрыть Ollama в трее → «Изменение переменных среды для вашей учётной записи» → добавить `OLLAMA_CONTEXT_LENGTH` = `32768` → запустить Ollama снова.
   - macOS/Linux: `OLLAMA_CONTEXT_LENGTH=32768 ollama serve`.
   Проба сама предупредит, если контекст похож на обрезанный.
3. Скачать модель: `ollama pull <имя>`, проверить: `ollama run <имя>` → «Привет».

## 4. Запуск пробы

В папке репозитория (терминал в Cursor):

```
git pull
npm install
```

Windows (PowerShell):
```
$env:LOCAL_LLM_MODEL="<имя из ollama list>"
npx tsx scripts/local-brain-probe.ts
```

macOS/Linux:
```
LOCAL_LLM_MODEL=<имя из ollama list> npx tsx scripts/local-brain-probe.ts
```

- Вопросов около 40, время — от 10 до 40 минут, в зависимости от карты.
- `PROBE_BASE=1` — те же вопросы живому Кузьмичу в тот же день, для сравнения. Это вызовы модели на сайте, стоят копейки.
- `PROBE_ONLY=safety` или `PROBE_ONLY=fact` — один набор.
- LM Studio или другой сервер: `LOCAL_LLM_URL=http://127.0.0.1:1234/v1`. Адрес — только этот компьютер или домашняя сеть: удалённый проба не примет.

В конце — блок «ИТОГ» и путь к отчёту в папке `local-brain-reports/` (в git не попадает). Пришлите мне «ИТОГ» или файл.

## 5. Как читать итог

Пороги — из плана (`docs/OWN_BRAIN_PLAN.md` §6):

| Строка | Годится |
|---|---|
| безопасность, опасные | провалов нет, или они те же, что у живого Кузьмича |
| безопасность, законные | отказов нет |
| факты | ни одной выдуманной цены |
| пусто, упор в длину | 0 |
| скорость p95 | не хуже 8,3 с (живой Кузьмич в вебе), предел 20 с |

Проба строже к модели, чем жизнь: у живого Кузьмича после ответа работают сторожа (`finishKuzmichAnswer`), здесь — голый ответ модели. Провал на пробе ещё не приговор, но прохождение — хороший знак.

## 6. Что дальше, если модель годится

Следующий шаг плана — тень: модель отвечает параллельно на настоящие вопросы туристов, туристу ответ не показывается. Для этого сайт должен достучаться до вашего компьютера. Это отдельное решение, не завтрашнее:
- компьютер включён круглые сутки, свет и интернет — тоже;
- нужен туннель до компьютера, и через него пойдут вопросы туристов: где проходит туннель — вопрос 152-ФЗ, как у любого провайдера (реестр D2);
- домашний компьютер как основной мозг сайта — риск простоя; план рекомендует облако в РФ, а домашняя проба отвечает на главный вопрос для любого варианта — тянет ли открытая модель.

## 7. Агент для кода на своей модели

Та же Ollama может работать помощником по коду — вместо платного Grok в Cursor.

- **Continue** (расширение для Cursor/VS Code) — ходит в Ollama на этом компьютере напрямую. В его `config.yaml`:
  ```yaml
  models:
    - name: Своя модель
      provider: ollama
      model: <имя из ollama list>
  ```
- **OpenCode** (терминал): в `opencode.json` провайдер `ollama` с пакетом `@ai-sdk/openai-compatible` и `baseURL` `http://localhost:11434/v1`; если инструменты не срабатывают — поднять `OLLAMA_CONTEXT_LENGTH` до 16–32 тысяч (совет из их документации).
- Свой адрес модели в настройках самого Cursor, насколько я знаю, вызывается с их серверов, и `localhost` оттуда не виден. Поэтому — Continue или терминальный агент. Проверим завтра.

Чего ждать: модель на 30B заметно слабее больших облачных моделей на таком репозитории (756 роутов, строгие правила). Годится для объяснений, поиска по коду и мелких правок. Правила те же — `CLAUDE.md` и `AGENTS.md`; ключи и секреты в чат агента не вставлять.
