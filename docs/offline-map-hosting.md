# Хранение своей карты (PMTiles) в Timeweb S3

Собранный файл — вся Камчатка в векторе, **92 МБ** (замер 09.08.2026). В образ
приложения он не помещается: лимит standalone-сборки на Timeweb — 50 МБ, и
превышение роняет деплой. Поэтому файл живёт в объектном хранилище, а
приложение читает его кусками.

## Что нужно от бакета

**Range-запросы.** PMTiles — это не архив, который скачивают целиком, чтобы
открыть. Клиент читает из него куски по диапазону байт: заголовок карты, потом
только те тайлы, что нужны экрану. S3 умеет это из коробки — проверить, что
работает, всё равно надо: без `206 Partial Content` формат бесполезен.

**CORS с ОТКРЫТЫМИ заголовками.** Это то место, где настройка ломается тихо.
Браузеру мало разрешения читать тело: если не открыть заголовки ответа, код
получит данные, но не сможет прочитать ни размер файла, ни его версию — а
именно по ним решается, можно ли продолжить прерванную закачку. Внешне всё
работает, пока человек не свернёт приложение на середине; тогда 92 МБ качаются
заново, и причина не видна ниоткуда.

Минимальные правила:

```json
[
  {
    "AllowedOrigins": ["https://vedarai.ru"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["Range", "If-Match", "If-None-Match"],
    "ExposeHeaders": ["Content-Length", "Content-Range", "Accept-Ranges", "ETag"],
    "MaxAgeSeconds": 86400
  }
]
```

**Публичное чтение.** Карта — открытые данные OSM, скрывать нечего, а
предподписанные ссылки живут часами и ломают докачку через сутки.

## Секреты в GitHub

Пока их нет, шаг выкладки пропускается молча — конвейер замера обязан работать
и без хранилища.

Бакет уже есть — тот, куда приложение кладёт фото. Второй заводить незачем:
карта ложится в папку `maps/` рядом. Значит и значения секретов уже известны,
их надо только скопировать в GitHub — прогон в CI не видит переменных Timeweb.

| Секрет в GitHub | Что вставить | Обязателен |
|---|---|---|
| `S3_BUCKET` | тот же бакет, что у фото | да |
| `S3_ACCESS_KEY` | тот же ключ доступа | да |
| `S3_SECRET_KEY` | тот же секретный ключ | да |
| `S3_ENDPOINT` | можно не задавать — по умолчанию `https://s3.twcstorage.ru`, как в приложении | нет |
| `S3_REGION` | можно не задавать — по умолчанию `ru-1` | нет |
| `MAP_S3_PUBLIC_BASE` | адрес, по которому файл открывается в браузере | желательно |

Если однажды понадобится отдельный бакет под карту, те же поля читаются под
именами `MAP_S3_BUCKET`, `MAP_S3_KEY`, `MAP_S3_SECRET`, `MAP_S3_ENDPOINT` — они
имеют приоритет над общими.

## Одно предупреждение про общий бакет

Правила CORS у бакета общие для всего содержимого. Фото ими не пользуются:
картинку браузер грузит целиком и заголовки ответа не читает. Карте нужны и
Range, и открытые заголовки — значит правила придётся дополнить на бакете,
который уже раздаёт фото на проде.

Дополнение безопасно: разрешение читать `Content-Range` и `ETag` ничего не
отнимает у картинок. Но менять настройки живого хранилища вслепую не стоит —
после правки откройте любое фото на сайте и убедитесь, что оно на месте.

`MAP_S3_PUBLIC_BASE` стоит задать, даже если кажется лишним. Хранилища раздают файлы
по-разному: одни путём (`эндпоинт/бакет/ключ`), другие поддоменом
(`бакет.эндпоинт/ключ`). Если адрес угадывать, проверка упадёт на **верно
настроенном** бакете — это худший вид ложной тревоги: чинить будут то, что не
сломано. Скопируйте адрес из панели хранилища; без него конвейер попробует
собрать его сам, но ручаться за догадку не станет.

## Имя файла — с датой, а не «latest»

Файл кладётся как `maps/kamchatka-ГГГГММДД.pmtiles`. Это не педантизм.

Карта, меняющаяся под одним и тем же адресом, ломает возобновление закачки:
куски, скачанные вчера, и куски, скачанные сегодня, сшились бы в файл, которого
никогда не существовало. Он не откроется — и выяснится это в поле, где скачать
заново нечем. Клиент защищается от этого сверкой версии, но защита срабатывает
как «начать заново», а датированное имя избавляет от ситуации вовсе: тот, кто
качает прямо сейчас, спокойно докачивает старый файл.

Переключение на новую карту — смена `NEXT_PUBLIC_MAP_PMTILES_URL` в переменных
окружения приложения.

## Проверка после настройки

Прогон сборки сам проверит хранилище и упадёт с объяснением, если что-то не так:
запросит первые сто байт с заголовком `Origin` и потребует `206` и
`Access-Control-Allow-Origin`. Проверять глазами раннера, а не надеждой —
дешевле, чем узнать о неверной настройке из браузера.
