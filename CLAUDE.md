# KamchatourHub — Claude Code Rules

> Туристическая платформа Камчатки. Цель: рабочий задеплоенный код без регрессий.
> Платформа также известна как **TourHab** / **Volcano OS**.
> Подробности об архитектуре, сервисах и хитростях — в `docs/DEVELOPER_GUIDE.md`; заметки «ждёт действия» и ловушки сессий — в `.claude/MEMORY.md`.
> **Offline-first**: ключевые функции (карта, SOS, маршруты) должны работать без интернета.


> **Это ядро правил (25.11, слово владельца «Разбей на скиллы»).** Подробные стандарты
> вынесены дословно в скиллы проекта `.claude/skills/vedar-*/SKILL.md`: Claude Code
> держит в контексте только их описания и загружает текст, когда задача его касается.
> Номера разделов сохранены: «CLAUDE.md §N» в коде и тестах ведёт к разделу ниже, а он
> называет скилл. При расхождении ядра и скилла верен скилл, ядро правится вслед.
> **Перед правкой в области скилла — загрузи его**, даже если правило кажется известным.

## 0. ГЛАВНОЕ ПРАВИЛО: ЧЕСТНОСТЬ (решение владельца 15.10)

> «Мы независимая платформа для туристов в первую очередь, и честность — наше
> главное правило. Запомни это.»

Ведар работает на туриста, а не на партнёра. Знакомство с партнёром, давность
отношений, просьба «чтобы выделялся» места на витрине не дают. Из этого:

- **Выделиться партнёр может только правдой о себе**: своими турами, своими
  снимками (с его согласием), своими словами в описании, отзывами туристов,
  фактами из базы (сколько живых туров и каких). На СВОЕЙ странице оператор
  вправе ставить свои туры вперёд (закрепление, 1267) — это его витрина.
- **Общие витрины** (список компаний, каталог, поиск, ответы Кузьмича и MCP)
  упорядочиваются одним правилом для всех, без ручных поднятий. Правило
  порядка называется туристу словами на самой странице.
- **Чужое правдивое не убирается ради партнёра.** Случай 15.10: оператор
  «Местечко Камчатка» не выделялся среди компаний, а обложкой другой компании
  стоял вертолёт. Проверка показала: кадр — с её собственного вертолётного
  тура. Он остаётся; вертолётные туры разных компаний стоят рядом.
- **Платное поднятие — только как реклама с маркировкой** (38-ФЗ, ст. 18.1,
  `docs/LEGAL.md`). Тайного продвижения нет.
- **Чего не знаем — так и говорим** (§4.0): нет отзывов — нет рейтинга, нет
  живых туров вида — нет фильтра по нему, не проверено — «не проверено».
- **Снимки партнёра — с его согласия, записанного, а не словами** (23.10):
  `partner_material_consents` (1321) хранит сам подписанный текст, ссылка из
  карточки партнёра в админке, страница `/partner-consent`, строка «партнёр
  разрешил … — согласие от …» только на его собственной странице. Текст
  называет, как Ведар использует материалы на деле; выбора «где показывать»
  нет, пока его нечем исполнить (ревью 23.10). Сторожа:
  `tests/unit/partner-materials-consent.test.tsx`,
  `tests/integration/partner-material-consent.pg.test.ts`.

Как это исполнено на витринах — скилл **`vedar-honesty`** (полный §0). Коротко:
- общий порядок туров один — `lib/tours/offer-order.ts` («правило 1в»: свободные
  места по ближайшему выезду, затем «в любой день сезона», остальные — жребий дня),
  подпись кончается «Место в списке не продаётся.»; компании на `/operators` — по алфавиту;
- партнёр на витрине — только через `publicPartnerSql`, тур — через `publicTourSql`
  (пауза и снятые компании отсечены), показ по уже бывшей ссылке — `tourOpenByLinkSql`;
  сравнение `is_public = TRUE` руками — красный;
- снимки партнёра — с записанным согласием, оферта — с отметкой и журналом акцепта;
- виджет на сайте партнёра показывает только его живые туры и сам заявок не создаёт.

## 4. КОД

Полностью — скилл **`vedar-code-rules`**. Коротко:

- **§4.0 Третье состояние (правило владельца 19.08).** У всякого поля и всякой проверки
  должен быть исход «не знаю»: место, где его нельзя сказать, заполняется враньём. Тип
  допускает отсутствие (`number | null`, не выдуманные 4.5); у проверки три исхода —
  «хорошо», «плохо», «не смог проверить», и третий не равен первому; отказ не глушится
  (пустой `catch` запрещён, имя проверки и SQLSTATE — в лог); промпт не требует того,
  чего нет в данных; ноль результатов при нулевом входе — отказ, а не успех.
- **Объявленный исход без источника (правило 10.09).** У всего объявленного —
  производитель, потребитель и сторож, в том же PR. Сторож держит связку, а не
  половину; непроизводимое записывается с причиной (`KNOWN_UNPRODUCED`,
  `KNOWN_UNCONSUMED`); докстрока, обещающая путь, которого нет, — дефект кода.
- **Сторож судит поведение, не текст (решение владельца 13.10).** Правило проверяется
  рендером и данными; регулярка по исходнику — только для запретов. Сторож на
  сторожей — `tests/unit/guards-judge-behavior.test.ts`.
- **Случай 24.08 (42P08).** `INSERT … SELECT $1 … WHERE NOT EXISTS` без якоря типа
  не выполняется никогда. Приговор — `PREPARE` на настоящем сервере, полноту реестра
  держит `tests/unit/sql-param-cast-shape.test.ts`; судить статикой ЗАПРЕЩЕНО.

**Обязательно:**
- TypeScript строгий — `unknown` + type guards, без `any`
- Все API routes — Zod валидация входных данных
- JWT проверка на каждом защищённом маршруте
- SQL — только параметризованный (`$1, $2`), никогда конкатенация
- Ошибки — понятные сообщения на русском
- Никаких эмодзи в коде, UI, логах

**Запрещено:**

  модуль трансферов, `operators`, `payments`, `payouts` и документы туриста.
  Список заморожен сторожем `tests/unit/schema-coverage.test.ts` и может
  только сокращаться
- `console.log` в продакшн-коде
- Секреты в коде — только `.env.local`
- Изменение схемы БД без SQL-миграции

### 5.1 Рутина сессии — на Sonnet (решение владельца 19.09)

**Подметание и вычитывание делает субагент на Sonnet, не главная сессия.**

Повод — счёт Anthropic за месяц (21.08–19.09, выгрузка владельца): **$114.92**,
и разложился он не так, как ожидалось:

| | |
|---|---|
| запись в кэш | **$49.96** (43%) |
| чтение из кэша | $30.51 (27%) |
| выход — то, что модель написала | $18.73 (16%) |
| вход без кэша | $15.72 (14%) |

То есть **70% счёта — кэш, а не работа моделей**. Запись в кэш стоит дороже
обычного входа (5 минут — ×1.25, час — ×2), чтение — ×0.1, и запись платится
заново каждый раз, когда контекст главной сессии подрос или пауза между
репликами пережила TTL. Из $114.92 платформа потратила $16.72 (прогон 7
`os-audit`, окно 200k–1M, Fable 5.1); остальные **85% — агентные сессии**.
Opus 5 — $56 из $115.

Отсюда правило. Работа, где нет рассуждения, а есть перебор и вычитывание,
идёт в субагента: у него свой контекст, своя цена, и наружу он отдаёт вывод
на несколько строк вместо прочитанного. Это режет и цену модели, и рост
кэша — то есть обе главные строки счёта.

| Субагент | Что ему отдавать |
|---|---|
| `poisk` | «где это лежит», «кто зовёт», «есть ли сторож на X» — подметание по 756 роутам, 173 компонентам, 11.6k тестов |
| `razbor-vyvoda` | длинный машинный вывод: полный прогон набора, лог CI, ответ переписи, выгрузка расхода, портянка линтера |

**Что остаётся главной сессии и на флагмане:** решение, чем чинить; правка
кода; сторож и проверка его мутацией; всё, что читает турист; всё, что
касается безопасности (§7, SOS, деньги). Сэкономить на решении — не экономия.

**Оба субагента только читают.** Правку делает тот, кто отвечает за неё
перед владельцем.

Сторож: `tests/unit/routine-on-sonnet.test.ts` — держит связку целиком
(субагенты существуют, приколоты к Sonnet, ничего не правят, и это правило
на них ссылается). Приколотая модель без правила, которое их зовёт, — конфиг
в никуда (§10.09).

**Две инструкции приведены к правилу (слово владельца 13.11 «2 да»).** Скилл
разбора кабинета роли раздавал пакеты правок помощникам, а команда
`/parallel-dev` запускала двух агентов, которые писали API и UI. Теперь в
обоих помощники читают, а код пишет главная сессия. Тот же сторож держит
запрет: оборот, которым правка отдавалась помощнику, не возвращается ни в
одну команду и ни в один скилл проекта. Новую формулировку той же мысли он
не поймает.

**Разбор за сутки (`day-review`) — то же правило в скрипте (слово владельца
13.11 «2 и 3 да делай»).** До этого дня в его скриптах модель не задавалась, и
все агенты разбора шли на модели сессии. Теперь темы влитого и открытые PR
читает Sonnet. На модели сессии остаются тревоги дайджеста, предложения
агентов и внешних авторов, проверка полноты, тема с пометкой `careful`
(SOS, 112, деньги, ПД) и вся проверка качества. Сторож —
`tests/unit/day-review-models.test.ts`: исполняет оба скрипта с подставными
агентами и судит, с какой моделью каждый вызван.

### 5.2 Как писать владельцу (слово владельца 13.11)

**Читатель отчёта не видел работы.** Владелец не видел ни вызовов
инструментов, ни файлов, ни хода рассуждений. Он приходит с других дел и часто
читает с телефона. Сообщение должно быть понятно само по себе.

Повод — руководство Anthropic по Fable 5.2, раздел о понятных отчётах: после
долгой работы модель пишет плотно и своими словами. Правило относится к
ответам в сессии, описаниям PR, комментариям в issue и отчётам скиллов.
Тексты для туристов и партнёров идут по §0 и своим стандартам.

- **Главное — в первых фразах.** Что сделано, что уже на проде, что нужно от
  владельца. Подробности — ниже. Первая строка не ссылается на то, что
  объяснено в двенадцатой.
- **Простые слова и полные предложения.** Одно предложение — одна мысль.
  Действительный залог. Одна вещь называется одним словом во всём тексте.
- **Ярлык, придуманный в работе, в отчёт не идёт.** «Срез 5», «прогон 182»,
  «волна 1б», имя ветки — слова исполнителя. Вместо ярлыка сказано, что это:
  «пятая часть правки», «перепись маршрутов на проде». Номер PR и issue
  оставлять можно: по нему владелец найдёт само дело. Имя файла или функции
  уместно там, где читатель будет его искать (описание PR, находка с
  `file:line`); в ответе владельцу сказано, что эта вещь делает.
- **Связные мысли — абзацем, отдельные пункты — списком.** Список из
  обрывков без сказуемых читается как шифр.
- **Лишнее не пишется, нужное не выбрасывается.** Нужное — числа, по которым
  решают («52 из 75»), что на проде, что ждёт слова владельца.
- **Вопрос владельцу — такой, чтобы ответить одним словом.** Варианты с
  номерами; у каждого — что будет сделано и чего это стоит.
- **Отчёт кончается строкой «Не проверено:»** — что осталось без проверки и
  почему. «Не смог проверить» не равно «хорошо» (§4.0).

Длину правило не задаёт: жёсткий предел («не длиннее N слов») эта модель
исполняет буквально, и текст выходит рубленым.

Стиль текста сторож судить не умеет, и это названо. Он держит только связку:
шаг «Отчёт владельцу» скилла `day-review` ссылается на этот раздел, и раздел
есть (`tests/unit/day-review-models.test.ts`).

## 6. ДЕПЛОЙ

```bash
npx tsc --noEmit      # 0 ошибок
npx vitest run        # весь набор зелёный (число растёт — сверяться с прогоном, не с этой строкой)
npm run lint          # 0 ОШИБОК обязательно; предупреждения печатаются и не блокируют
git push origin main  # → CI на main → deploy.yml выкатывает проверенный sha (схема в скилле)
```

Полностью (§6, «Database Migrations», §6.1) — скилл **`vedar-deploy`**. Коротко:
- **Выкат только проверенного коммита (решение владельца 15.10).** Push в main → CI на
  всех путях → зелёный CI → `deploy.yml` заказывает у Timeweb сборку ровно этого sha и
  сверяет, что прод его отдаёт; красный CI на main — выката нет, `ci-red-alert` шлёт
  тревогу. Автодеплой Timeweb выключается маркером `.github/triggers/timeweb-configure.json`;
  ручной выкат — `workflow_dispatch` у `deploy.yml`.
- Линт — отдельный job `lint`. Предупреждения эры React Compiler — индикатор дрейфа,
  разбирать их скопом ЗАПРЕЩЕНО (разбор #885). eslint 10 не ставить (#1244).
- **Timeweb:** приложение **Tourhab**, id `198048`; переменные окружения — в панели
  Timeweb, не в коде; `ignoreBuildErrors=true` на Timeweb, локально — строгая проверка.
- **Миграции:** `migrations/NNN_name.sql`, идемпотентны, применяются при каждом деплое
  через `start.js`; **НИКОГДА** не применять через HTTP endpoint; `docs/DB_SCHEMA.md`
  руками в PR не перегенерировать.
- **Docker (§6.1):** standalone не больше 50 МБ; `images.unoptimized: true` не убирать;
  в runner stage не копировать `node_modules` и не ставить пакеты.

## 7. НЕ ТРОГАТЬ

**Проверка зон (15.10, владелец: «по статье Anthropic тебе карт-бланш»).** PR, задевший зону ниже,
краснеет без раздела `## Слово владельца` в теле: по строке на зону — имя зоны или путь, цитата «…»
и дата ДД.ММ; правка одних комментариев — предупреждение. Реестр зон с причинами (он сам тоже зона) —
